# 手机与电脑自动同步设计

日期：2026-10-27（北京时间）

状态：用户已同意自动云同步的方向；本文供书面设计审阅，尚未实现或部署。

## 目标与现状

用户希望手机与电脑共享复习数据。已确认目前网站为 GitHub Pages 静态页面，新成绩在 `review-study-store.js` 中写入各自浏览器的 localStorage；现有导出、导入可以合并成绩，但没有云端副本。

保留现有地址 `https://flyyuan1.github.io/zyz-reading-review/`、175 篇文章、原题、评分规则及学习计划算法。两端只需配对一次，之后自动合并学习记录，分别保留两端已有历史。

## 选择的方案

增加独立的 Sites 云同步服务和 D1 数据库；现有 GitHub Pages 页面通过 HTTPS 调用该服务。此前已确认可以使用 Sites 提供服务与持久化数据库，且不需要改造文章页面为服务器渲染。

备选方式为继续手工导出／导入（现有功能，可立即迁移，但每次要操作），或将整个站迁移到需要登录的新域名（可按账号同步，但需要换网址并迁移浏览器记录）。选用独立服务以保留现有复习入口。

服务需要接受来自手机和电脑的网络请求，因此部署为公开可访问的 API；公开的是接口地址，每个学习空间均要求独立凭据，禁止匿名读取或修改成绩。**本次书面审阅包含对新同步 API 公开网络可达的确认；学习记录本身保持私密。** 不修改已有其他 Sites 的内容或访问权限。

## 同步范围与配对

- 同步已交卷的本站测试成绩、用时、作答与辅助标记，以及已导入的原站记录。
- 错题、满分覆盖、复测任务和学习进度由现有算法按合并后的记录重新计算，避免另存一套可能不一致的统计。
- 计划设置记录用户修改时间；只在确有保存的设置时参与同步，不用新设备的默认值覆盖已有设置。同一字段冲突采用较新的明确修改，时间相同则按稳定规则选择，并显示冲突提示。
- 未交卷草稿、阅读位置和筛选条件仍保存在当前设备，本轮不承诺跨设备接续未完成的考试。同步过程中不得覆盖正在填写的答案。
- 电脑在「计划与成绩」点击「启用同步」，生成由安全随机数产生的高强度配对码；手机在同一位置输入或粘贴配对链接。已存在的两端历史自动加入同一个空间。
- 配对链接只在 URL fragment 中携带密钥，接收后立即清除地址栏中的密钥；不放入查询参数、服务器日志或公开源码。配对码相当于该空间的访问钥匙，界面说明只分享给自己的设备。
- 配对页提供「复制配对码／链接」「立即同步」「断开本机同步」。断开只移除本机连接信息，不删除本机历史或云端记录。

## 云端数据保护与接口

浏览器使用 Web Crypto 从配对密钥派生不同用途的身份凭据、AES-GCM 加密密钥和记录标识密钥。成绩正文先在浏览器加密，再上传到云端；服务器不接收原始备份文件、原文题库或明文答案。

D1 存储空间的凭据校验值，以及加密记录的标识、密文、顺序号和协议版本。每条测试／原站记录独立加密，采用有限批次上传和分页拉取，不把全部历史塞进一个数据库单元格。新增 schema 使用受版本管理的迁移，不在请求中临时建表。

预期接口：创建空间、按游标读取记录、追加一批加密记录。每个读写操作均校验空间凭据；空间查询必须包含空间 ID，防止跨空间读取。记录标识通过带密钥的内容摘要产生，相同记录重复上传幂等；修改后的原站版本保留为独立密文版本。

API 严格限制请求大小、单条记录大小、批次数量和分页数量；校验协议版本与字段类型。CORS 只允许现有 GitHub Pages 的 origin，以及明确配置的本地开发 origin。CORS 不作为身份校验的替代。服务报错不得返回密钥、答案或内部异常细节。

## 合并与失败恢复

1. 首次配对先将当前设备的有效记录纳入待上传队列，同时分页拉取已有云端历史。
2. 本站测试按提交 ID 去重；原站记录复用现有 `mergeSources` 的完整性检查与补全规则。不同 ID 的测试全部保留。
3. 相同 ID 的内容或原判分出现矛盾时，保留本机可靠记录，并保留远端加密版本供后续核对；显示冲突数量，不静默覆盖或伪造新提交。
4. 先完成校验及本机持久化，再推进已处理游标。因空间不足、解密失败或格式错误无法保存时，不将这一批记为已完成；恢复后可重新拉取。
5. 交卷和导入后触发同步；回到页面及重新联网时再次同步；页面可见时定期检查其他设备的新记录。串行执行同步任务，避免本机并发覆盖队列。
6. 断网时照常在本地保存作答、交卷和成绩；联网后重试上传。失败重试使用退避，不无限频繁请求。
7. 显示「未连接」「同步中」「已同步／上次成功时间」「离线，待同步」「同步失败」「存在冲突」。仅在本轮待上传记录已被确认、远端分页已处理后显示已同步。
8. 保留原有导出／导入作为备份及恢复途径。清理浏览器数据后仍需要配对码重新加入；没有配对码时不能从密文找回成绩。

## 变更边界

前端增加独立的同步协议、同步客户端与配对界面模块；对现有 Store 和相关页面事件作最小接入。更新页面生成脚本与发布文件的缓存版本，避免重新生成后丢失同步入口。更新使用说明与隐私说明。

根目录、`github-pages-site` 和 `github-upload-checkout` 的发布资产保持一致。同步服务在独立目录管理自己的源码、迁移和 Sites 身份，不把服务凭据写入 GitHub 仓库。

## 验收

- 两个互相隔离的浏览器上下文模拟手机、电脑：分别已有不同成绩，配对后两端得到并集，重复同步不增加重复测试。
- 在任一端新交卷或导入原站记录，另一端同步后得到相同历史、错题统计与计划结果。
- 验证断网后交卷、重新联网、请求中断、分页重试及服务重启后数据仍保留。
- 验证错误配对码、跨空间请求、伪造／篡改密文、大请求与原站判分冲突，确保拒绝错误操作并保留可靠数据。
- 验证导出／导入仍可用，原有 Store、原站合并、评分与计划测试通过。
- 以手机窄屏和电脑宽屏检查配对入口及状态；同步不得改变当前未交卷草稿。
- 部署服务及前端后，再使用不含个人答案的合成记录做线上双端验证；最终交付同步入口与首次配对步骤，并明确实际验证范围。

## 发布顺序与执行方式

先完成云端和前端实现及本地验证，再部署同步服务，最后发布 GitHub Pages 客户端并验证。服务未就绪前，不让现有页面显示可用的云同步入口。旧的本地记录始终保留。

建议在本聊天中按书面实施计划顺序执行。书面设计批准后，按 brainstorming 技能要求使用 writing-plans 技能编写实施计划，再提交计划供用户审阅并选择执行方式；在这些审阅完成前不创建外部项目、不修改产品代码、不部署。
